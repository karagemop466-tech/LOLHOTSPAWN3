Method & source audit

How every number on this site is produced, and what was checked when it could not be.

Pipeline

  1. Inventory. GET https://play.hotspawn.com/lol-pickems — the page is Angular SSR and embeds its fixture list in <script id="ng-state">. All 264 LoL fixtures are read from that JSON (id, competition, teams, kick-off, tier, stage, points). Hotspawn's crowd-pick percentages are captured but never used as a probability input.
  2. Match links. Each rendered card contains the canonical https://www.hotspawn.com/matches/… URL; those are extracted so every row links to its source.
  3. Prices. Pinnacle (guest API, no key) and Thunderpick (via bo3.gg) LoL moneylines are pulled for all competitions those books list.
  4. Mapping. A price is attached to a fixture only when the kick-off times are within 8 hours and the normalised team-name similarity is ≥ 0.72 (either orientation). Otherwise the price is left unmatched and reported.
  5. Probability. Decimal odds → implied → remove the margin by normalisation. Primary book = Pinnacle; Thunderpick is the cross-check.
  6. Unresolved. No attached price ⇒ no probability. The fixture is published on Unresolved with the sources that were checked.

Verification rules applied

  • Every match row links to its Hotspawn match page (or the lobby, where Hotspawn renders no card).
  • Every probability row links to the exact external price it came from.
  • No value is filled in by inference. Missing ⇒ blank + flagged.
  • Name matching is logged with a score; low-confidence links are rejected, not published.
  • If the Hotspawn lobby cannot be read, the last good dataset is kept and the failure recorded in data/collect-errors.json rather than publishing an empty site.

Refresh

GitHub Actions runs the collector every 6 hours (17 */6 * * * UTC) and on demand, then rebuilds this site. Cadence target from the brief: every 4–8 hours.

Known limitations

  • Hotspawn's own site is Cloudflare-protected for automated clients on www.hotspawn.com; the collector uses play.hotspawn.com, which serves the same fixture data.
  • Best-of format is null for every fixture in Hotspawn's transfer state, so the site does not display it.
  • Completed fixtures are listed but not graded; the project reports probabilities at collection time only.
